# Content Signals Policy (Cloudflare, 2026). Three machine-readable signals
# stating how this content may be USED, as distinct from whether it may be
# fetched:
#
#   search    — index it and show it in ordinary search results
#   ai-input  — ground a live AI answer on it (RAG, AI Overviews, assistants)
#   ai-train  — train or fine-tune a model on it
#
# All three are yes, deliberately. PropXchain is a pre-launch platform whose
# problem is being unknown, not being copied: we WANT to be the answer when
# somebody asks an assistant about digital conveyancing or the homebuying pack.
# That is the same reason we publish llms.txt and llms-full.txt and name every
# AI crawler below.
#
# This is stated explicitly rather than left implicit, because from 15 September
# 2026 the industry default flips towards ai-train=no, and silence will
# increasingly be read as refusal. Nothing here is enforcement — it is a
# declared preference a well-behaved crawler can act on.
#
# If this ever changes — if we sell data access, or host third-party content we
# do not own the rights to — this line is the one to revisit first.

# Default: allow all crawlers
# Clean URLs only (BrowserRouter, no #/ since 2026-06-13). The old
# Disallow: /#/... lines were dead — the # fragment never reaches the
# server, so it can't be matched. These block the real clean paths.
User-agent: *
Content-Signal: search=yes, ai-input=yes, ai-train=yes
Allow: /
Disallow: /admin
Disallow: /payment/success
Disallow: /reset-password
Disallow: /auth/confirm
